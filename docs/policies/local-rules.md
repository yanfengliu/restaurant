# Local product rules

- Build Corner Table as an original 3D browser restaurant management game with its own identity, names, assets, and game content.
- Use external games and developer posts as design research, and keep their attribution in research notes rather than product code or commit messages.
- Visual quality matters: study actual pixels and developer posts, then inspect rendered scenes, panels, camera angles, and real controls.
- Work headlessly unless a visible application is necessary and no headless alternative can verify the task; state the reason first.
- Own browser, GUI, server, and temporary processes by PID or identifiable session and clean only task-owned resources in a finally path.
- Leave a local server running only when the user asks for it to remain available.
- Preserve useful handoff evidence; remove task-owned temporary output when no active task needs it.
