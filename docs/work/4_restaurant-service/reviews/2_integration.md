## Reports

### Codex independent agent integration reviewer

**F2 — Medium: the wage ceiling rejects an accepted historical save when its tolerated clock discrepancy makes the derived day phase negative.** At target `59569c1`, `src/engine.js:1264` computes phase as `calendarSeconds - (day - 1) * DAY_SECONDS`. The unchanged clock validator at `src/engine.js:1157` permits the calendar and day/time representation to differ by up to `0.00001`. A literal historical `month-paid-at-boundary` save with `calendarSeconds = 449.999991`, `day = 31`, `time = 0`, and both `monthlyWage` and `wageAccrued` set to the valid maximum 22500 is accepted unchanged by the old engine at `1508bb3`, but the integrated engine rejects it with the accrued-wages error. Its computed phase is approximately −0.000009, reducing the new ceiling below the old full-salary balance. This violates the explicit preservation of the old validator's accepted money range. Derive a nonnegative day phase consistently with the accepted clock tolerance, retain historical validation tolerance, and guard the accepted boundary case through load, advancement, reload and one settlement. This is an accepted-save boundary finding, not a claim that the ordinary quarter-second clock generates this fixture.

The machine graph otherwise implements the reviewed contract coherently. Incoming reservations are derived from `machine-collect` and `machine-load`, while rack occupancy is derived from per-dish machine ownership (`src/engine.js:135-141`). Deposit replaces the employee claim with a rack claim before starting an exact five-unit batch (`src/engine.js:757-763`). Cycle advancement precedes staff processing in the simulation step, so a newly started batch does not consume its first quarter-second before the next step. The autonomous update changes all washing units together and removes the shared progress (`src/engine.js:151-157`). Clean pickup frees the machine slot, retains the cabinet return reservation and removes the employee's machine link (`src/engine.js:764-770`). These transitions do not create or discard ware records.

Unchanged storage callers support the extension: `reservedStorage` counts every `returnStorageId`, and `usedStorage` counts only stored clean ware (`src/engine.js:161-167`). This keeps one reserved return slot across all machine phases without treating rack output as clean cabinet stock. The strict new task/ware checks at `src/engine.js:1289-1333` require reciprocal owners and compatible targets, reject excess combined occupancy and inconsistent active batches, and retain per-type conservation. Historical sink task names and their validation remain separate. `resetStaff` and `setWare` now remove the new links as well as legacy ones (`src/engine.js:504-511`), preventing machine identity or rack age from leaking into clean inventory or an idle employee.

Route and cancellation behavior is consistent with the contract. Loading proves source, machine and cabinet access from the employee's reachable component. Unloading rechecks the reserved cabinet before taking the clean unit; a newly blocked return route releases only the unloader and leaves the rack/reservation intact (`src/engine.js:764-766`). The unchanged `replanStaff` blocked-state logic at `src/engine.js:615-620` and construction path rebuild at `src/engine.js:846-865` preserve held ownership when a route later closes. Collection dismissal releases both reservations; unload dismissal clears only the assignee (`src/engine.js:623-632`). Existing dismissal refusal for carried dishes remains effective for the shared carried states. Move and sale guards include both machine tasks and rack records, while exact no-op moves still return before changing state. The carried cancelled-meal disposal path remains intact and later joins ordinary dirty collection.

Breakage still occurs only on the first actual dirty-carry movement. Both old sink carry and new machine load use the persisted `breakageChecked` flag (`src/engine.js:704-711`); breaking a unit removes its record and therefore its return reservation, increments one ledger counter and resets its employee. Neither rack progression nor clean retrieval rerolls it. The tests pin a public candidate/seed trace that breaks at elapsed 184.25, compare the reload twin before the random step, and verify both reservations are released (`tests/service.test.js:185-202`).

Apart from F2, daily settlement preserves the intended accounting. The existing accrual rate is unchanged, each crossed day boundary pays the whole unpaid liability and clears it once (`src/engine.js:811-828`), and dismissal still pays only the remaining liability. `spend` remains the common cash, lifetime-expense and daily-expense writer (`src/engine.js:44-47`, outside the changed hunks). The new tests cover half-day hiring, pause, speeds, capped ticks crossing multiple days, month rollover, dismissal, bankruptcy, literal pre-change phases and old/new maximum debt bounds.
